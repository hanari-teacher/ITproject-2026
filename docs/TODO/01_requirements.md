# TODO機能 要件定義書 (V1)

## 1. 目的・対象範囲

### 1.1 目的

本要件定義書は、既存の Express + TypeScript + EJS アプリケーションに対して、Vercel および Neon PostgreSQL 環境上で動作するシングルページWebアプリケーション形式のTODO管理機能（V1）を追加・定義することを目的とします。

### 1.2 対象範囲

* **対象機能**: `/todo` 画面におけるタスクの一覧表示、新規登録、完了状態切り替え、削除（計4機能）。
* **対象環境**: Vercel（Preview / Production）、Neon PostgreSQL。
* **対象外 (V1)**: ユーザー認証・認可、優先度設定、フィルタリング・絞り込み、タイトル変更（更新）、マルチユーザー分離。

### 1.3 前提条件・制約

* 既存ルーティング（`/` および `/api/db-check`）と既存のDB接続設定（`DATABASE_URL`）をそのまま維持・継承します。
* Preview環境およびProduction環境は同一のNeon DBを参照します。個人情報は一切扱わず、テスト用・デモ用の架空データのみを使用します。
* 画面（`/todo`）はEJSで初期枠組みをレンダリングし、ブラウザ（`public/todo/todo.js`）から Fetch API を用いて REST API（`/api/todo/v1/todos`）を操作します。
* モジュール構成や `TodoApi` クラス等の詳細設計、およびプロジェクト直下ファイル（`db.ts` 等）の具体的なデータアクセス実装は「要確認」とし、設計書（`02_design.md`）にて決定します。

## 2. 4機能と受け入れ条件

### 2.1 REQ-01: タスク一覧取得

* **操作**: 画面初期表示時、またはデータ更新後に自動実行。
* **入力**: なし（`GET /api/todo/v1/todos`）
* **結果**:
* 登録済みタスクの配列を取得し、画面に一覧描画します。
* データが0件の場合は空配列 `[]` を返却し、画面上には「TODOはありません」等のメッセージを表示します。


* **エラー**: 500（DB接続・クエリエラー）、503（DB応答不全）。
* **受け入れ条件**:
* 画面ロード時に自動で一覧が描画されること。
* 0件の場合にエラーとならず、正常に200レスポンスと空配列を受け取れること。


* **確認方法**: ブラウザで `/todo` にアクセスし、開発者ツールの Network タブで 200 OK と JSON 配列が返却されていることを確認する。

### 2.2 REQ-02: タスク新規登録

* **操作**: 画面の入力フォームにタイトルを入力し、「追加」ボタンを押下。
* **入力**: `title`（文字列）
* バリデーション: 前後の空白を除去（trim）した結果が **1文字以上100文字以下**。


* **結果**:
* データベースにタスクを未完了状態（`completed: false`）で保存。
* HTTP 201 Created と作成されたタスクオブジェクトを返却し、画面の一覧を再描画（または要素追加）します。


* **エラー**:
* 400: リクエストボディの形式不正。
* 422: `title` が空、またはトリム後100文字超過。
* 500 / 503: サーバー・DBエラー。


* **受け入れ条件**:
* 前後の空白を自動除去して保存されること。
* 1〜100文字のテキストが正常登録され、一覧に即座に反映されること。
* 0文字または101文字以上の場合は画面上にエラーメッセージが表示され、APIが422を返すこと。


* **確認方法**: 入力欄にテスト文字列（前後スペース含む、限界値100文字等）を入力して送信し、表示結果とDB上の登録データを確認する。

### 2.3 REQ-03: 完了状態の部分更新

* **操作**: 一覧上のチェックボックスの操作（ON/OFF）。
* **入力**: パスパラメータ `id`（1以上の整数）、`completed`（真偽値: `true` / `false`）
* **結果**:
* 指定IDのタスクの `completed` 状態を更新。
* HTTP 200 OK と更新後のタスクオブジェクトを返却します。


* **エラー**:
* 400: `id` が1以上の整数でない、または `completed` が boolean でない。
* 404: 該当する `id` のタスクが存在しない。
* 500 / 503: サーバー・DBエラー。


* **受け入れ条件**:
* チェックボックスの切替に応じて、即座に該当タスクの完了/未完了状態が更新されること。
* 存在しないIDを指定した場合は404エラーとなること。


* **確認方法**: 画面のチェックボックスを操作し、レスポンスの `completed` 値と画面表示の変更を確認する。

### 2.4 REQ-04: タスク削除

* **操作**: 一覧上の各タスク横にある「削除」ボタンを押下。
* **入力**: パスパラメータ `id`（1以上の整数）
* **結果**:
* 該当タスクをデータベースから物理削除。
* HTTP 204 No Content（レスポンス本文なし）を返却し、画面一覧から対象項目を削除します。


* **エラー**:
* 400: `id` が1以上の整数でない。
* 404: 該当する `id` のタスクが存在しない。
* 500 / 503: サーバー・DBエラー。


* **受け入れ条件**:
* 削除成功時に 204 No Content が返り、本文が空であること。
* 画面上から該当タスクが消去されること。


* **確認方法**: 削除ボタンを押下し、Network タブで 204 返却とレスポンスボディが空であることを確認する。

## 3. 共通のデータ・エラー条件

### 3.1 データモデル概念構造

```json
{
  "id": 1,
  "title": "要件定義書を作成する",
  "completed": false,
  "created_at": "2026-11-10T00:00:00.000Z",
  "updated_at": "2026-11-10T00:00:00.000Z"
}

```

* **id**: 1以上の整数（自動連番）
* **title**: 文字列（前後の空白を除いて 1〜100 文字）
* **completed**: 真偽値（新規作成時は `false` 固定）

### 3.2 レスポンス・エラー形式（TODO専用仕様）

#### 成功時レスポンス

* **GET /api/todo/v1/todos**: `200 OK`
```json
[
  {
    "id": 1,
    "title": "タスク例",
    "completed": false,
    "created_at": "2026-11-10T00:00:00.000Z",
    "updated_at": "2026-11-10T00:00:00.000Z"
  }
]

```


* **POST /api/todo/v1/todos**: `201 Created`（作成されたオブジェクト単体を返却）
* **PATCH /api/todo/v1/todos/:id**: `200 OK`（更新後のオブジェクト単体を返却）
* **DELETE /api/todo/v1/todos/:id**: `204 No Content`（レスポンス本文なし）

#### エラー時共通レスポンスフォーマット（TODO専用）

```json
{
  "error": {
    "code": "ERROR_CODE_NAME",
    "message": "ユーザー向けエラーメッセージ"
  }
}

```

#### 各ステータスコードの発生条件

| ステータスコード | エラーコード | 発生条件 |
| --- | --- | --- |
| **400 Bad Request** | `BAD_REQUEST` | IDが1以上の整数でない、JSON形式不正、パラメータの型違背 |
| **404 Not Found** | `NOT_FOUND` | 指定された `id` のタスクがDB上に存在しない場合 |
| **422 Unprocessable Entity** | `VALIDATION_ERROR` | `title` のトリム後長さが0文字または100文字を超えている場合 |
| **500 Internal Server Error** | `INTERNAL_SERVER_ERROR` | サーバー内部例外、DBクエリ実行エラー等 |
| **503 Service Unavailable** | `SERVICE_UNAVAILABLE` | Neon PostgreSQLへの接続タイムアウト・障害 |

## 4. 環境別確認

### 4.1 ローカル開発環境（Local）

* **確認内容**: Node.js 上で Express サーバーを起動し、`.env` に設定された Neon DB（開発用/共通DB）に接続して `/todo` 画面および各APIが意図通り動作することを確認する。
* **確認項目**: バリデーション動作（422/400）、CRUD一連の操作、開発者ツールでの204レスポンス確認。

### 4.2 Vercel Preview 環境

* **確認内容**: Pull Request 等に伴い作成される Preview URL 上で、Vercel の環境変数 `DATABASE_URL` 経由で Neon DB に正常接続できることを確認する。
* **確認項目**: 静的ファイル（`public/todo/todo.js`）の配信、APIルーティングのレスポンス速度、ビルドエラーの有無。

### 4.3 Vercel Production 環境

* **確認内容**: 本番ドメイン上で安定動作することを確認する。
* **確認項目**: 架空データのみでの運用確認、既存 `/` および `/api/db-check` への影響がないことの回帰テスト。
