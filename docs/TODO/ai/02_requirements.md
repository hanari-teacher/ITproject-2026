# AI質問機能 要件定義書 (`02_requirements.md`)

## 1. 文書概要・位置づけ

本書は「AI質問機能 追加要望書 (`01_request.md`)」および最新の Gemini モデル提供方針をもとに、システム開発に必要な**機能詳細・入力制約・画面遷移・非機能基準・受け入れ基準**を確定させる要件定義書である。

本ドキュメントの確定内容をもとに、次工程である「設計フェーズ (`docs/ai/03_design.md`)」にてAPIインターフェース仕様・詳細設計・画面レイアウト設計を行う。

---

## 2. システム概要・開発スコープ

### 2.1. 基本方針・利用基盤

* **対象システム**: 既存の Express / TypeScript / EJS 製 Webアプリケーション
* **対象ユーザー**: 本アプリケーションを利用する一般ユーザーおよび管理者
* **採用AIプラットフォーム**: **Google Gemini API**
* **採用SDK**: Google Gen AI 公式 TypeScript/JavaScript SDK（`@google/genai`）
* **標準採用モデル**: **`gemini-3.5-flash-lite`**
* 従来の `gemini-2.5-flash` の非推奨化（2026年12月1日以降の自動ルーティング移行）に対応し、低レイテンシかつ高コストパフォーマンスな後継モデルである `gemini-3.5-flash-lite` を標準モデルとして採用する。
* 将来的な要件変化（高度な推論が必要な場合など）に備え、環境変数経由で `gemini-3.8-flash` 等の Gemini 3 系モデルへコード改修なしで切り替え可能な構成とする。



### 2.2. 開発スコープ定義

| 区分 | 対象範囲 |
| --- | --- |
| **スコープ内（対象）** | ・AI質問専用画面（`GET /ai`）の提供および既存画面からの導線確保<br>

<br>・単発のテキスト質問に対するAI回答生成・非同期表示機能<br>

<br>・フロントエンドおよびバックエンド双方での入力バリデーション<br>

<br>・APIエラー・レート制限・タイムアウト・不正入力時のユーザー向けエラー通知および例外連携<br>

<br>・環境変数によるAPIキーおよび使用モデルの外部設定化 |
| **スコープ外（対象外）** | ・質問および回答履歴のデータベース永続化・履歴一覧閲覧機能<br>

<br>・過去の対話文脈を引き継ぐマルチターン（連続会話）機能<br>

<br>・ストリーミング（逐次文字表示）形式でのレスポンス配信（一括返却方式を採用）<br>

<br>・新規のユーザー認証・アクセス権限管理機能の実装 |

## 3. 画面構成・画面遷移要件

### 3.1. 画面遷移フロー

1. ユーザーは既存画面（TOP画面またはTODO画面）のナビゲーションリンクから **AI質問画面（`GET /ai`）** へ遷移する。
2. AI質問画面上で質問文を入力して送信すると、ページリロードを伴わず、非同期通信（Fetch API）でバックエンドへリクエストを送信する。
3. 処理完了後、同一画面内の回答表示エリアにAIの回答（またはエラーメッセージ）を描画する。
4. 画面内の戻りリンクから既存のTOP / TODO画面へ遷移できる。

```text
[既存 TOP / TODO画面] ──(リンク遷移: GET /ai)──> [AI質問画面 (/ai)]
       ▲                                                │  ▲
       └──────────(戻りリンク遷移)──────────────────────┘  │ (非同期通信: 質問送信・回答描画)
                                                           ▼
                                                  [Express バックエンド]
                                                           │
                                                           ▼
                                           [Google Gemini API (gemini-3.5-flash-lite)]

```

### 3.2. 画面構成要素要件 (`views/ai/index.ejs`)

| エリア名 | 必須要素 | 機能・表示要件 |
| --- | --- | --- |
| **ヘッダー領域** | 画面タイトル・ナビゲーション | 機能名（「AI質問アシスタント」等）を表示し、既存TOP / TODO画面への戻りリンクを配置する。 |
| **質問入力領域** | テキストエリア・文字数表示・操作ボタン | ・複数行入力可能なテキストエリアを設置する。<br>

<br>・現在の入力文字数および上限文字数（`0 / 1000`）をリアルタイム表示する。<br>

<br>・「送信」ボタンおよび入力内容・回答をリセットする「クリア」ボタンを設置する。 |
| **状態通知領域** | ローディング表示・エラー表示 | ・AI応答待機中はローディングインジケーター（例: 「回答を生成中...」）を表示する。<br>

<br>・バリデーションエラーや通信エラー発生時は、視認性の高いエラーメッセージ枠を表示する。 |
| **回答表示領域** | 回答テキスト表示枠 | ・初期表示時は案内プレースホルダー（例: 「質問を入力して送信してください」）を表示する。<br>

<br>・回答受信後は、改行や段落構造を保持した状態で回答テキストを表示する。 |

## 4. 機能要件

### 4.1. 機能一覧

| 機能ID | 機能名 | 概要 |
| --- | --- | --- |
| **F-01** | AI質問画面表示機能 | `GET /ai` リクエストに対し、EJSテンプレートをレンダリングして質問画面を返却する。 |
| **F-02** | 入力バリデーション機能 | 送信された質問テキストの型・必須・文字数制限をフロントエンドおよびバックエンドで検証する。 |
| **F-03** | Gemini AI 連携・回答生成機能 | 検証済みの質問テキストを `@google/genai` 経由で Gemini API に送信し、回答テキストを取得する。 |
| **F-04** | 非同期UI制御・回答描画機能 | 送信中の二重送信防止、ローディング表示切り替え、および受信データの安全なDOM描画を行う。 |
| **F-05** | エラーハンドリング・例外連携機能 | 各種エラーを適切に分類し、HTTPステータスとユーザー向けエラーメッセージを返却する。予期せぬ例外は既存エラーハンドラーへ委譲する。 |

### 4.2. 入力制約・バリデーション基準 (F-02)

リクエストパラメータ（質問テキスト）に対して、以下の制約を適用する。フロントエンド（UX向上・不要通信抑止目的）とバックエンド（セキュリティ・整合性担保目的）の双方で検証を実施する。

| 項目 | 制約・ルール | エラー時の挙動 |
| --- | --- | --- |
| **データ型** | 文字列型（`string`）であること（配列・オブジェクト・数値・`null` 等は不可） | HTTP `400 Bad Request` を返却 |
| **必須チェック** | 未入力（`undefined` / 空文字 `""`）および半角・全角スペース・改行のみの文字列は不可 | 「質問内容を入力してください。」を表示（`400`） |
| **最小文字数** | 前後の空白除去（`trim()`）後、**1文字以上** | 「質問内容を入力してください。」を表示（`400`） |
| **最大文字数** | 前後の空白除去（`trim()`）後、**1,000文字以下** | 「質問は1,000文字以内で入力してください。」を表示（`400`） |

### 4.3. Gemini AI 連携仕様 (F-03)

* **SDK初期化**: `dotenv` で読み込んだ環境変数 `AI_API_KEY` を使用して `GoogleGenAI` クライアントを初期化する。
* **使用モデル**: 環境変数 `AI_MODEL` で指定可能とする。未設定（または空文字）の場合のデフォルト値は **`gemini-3.5-flash-lite`** とする。
* **プロンプト・システム指示方針**:
* ユーザーの質問に対して正確かつ簡潔、分かりやすい表現で回答を生成するようシステム指示（`systemInstruction`）を設定する。
* 原則として質問と同じ言語（主に日本語）で応答する。


* **空応答への対処**: APIから有効なテキストが返却されなかった場合（安全フィルタによるブロックや空レスポンス等）は異常系として扱い、エラーメッセージを返却する。

### 4.4. エラーハンドリング基準 (F-05)

| エラー分類 | 想定原因 | HTTPステータス | ユーザー向け表示メッセージ | バックエンド処理 |
| --- | --- | --- | --- | --- |
| **入力値不正** | 空文字、空白のみ、文字数超過、不正な型 | `400 Bad Request` | 具体的な入力修正を促すメッセージ | コントローラー層で検証し、JSON形式でエラー応答を返却 |
| **レート制限超過** | Gemini API のクォータ・レート上限（429） | `429 Too Many Requests` | 「現在リクエストが集中しています。しばらく時間を置いて再度お試しください。」 | サービス層で捕捉し、レート制限エラーとして応答 |
| **外部API障害** | ネットワーク断、Gemini APIサーバーエラー、空応答 | `502 Bad Gateway` | 「AIサービスとの通信に失敗しました。時間をおいて再度お試しください。」 | サービス層で例外捕捉し、生スタックトレースを隠蔽 |
| **API設定不備** | `AI_API_KEY` 未設定、または無効なAPIキー（401/403） | `503 Service Unavailable` | 「AIサービスの設定に問題があります。管理者にお問い合わせください。」 | サーバーログにエラー種別のみ記録（APIキー値は出力しない） |
| **タイムアウト** | 外部AI APIの応答遅延（30秒超過） | `504 Gateway Timeout` | 「AIからの応答がタイムアウトしました。質問を短くするか、時間をおいて再度お試しください。」 | リクエストを中断（Abort）し、タイムアウトエラーとして処理 |
| **予期せぬ例外** | 上記以外のランタイムエラー | `500 Internal Server Error` | 既存のエラーハンドラー仕様に準拠 | `next(err)` を呼び出し、既存のグローバルエラーハンドラーへ連携 |

## 5. 非機能要件

### 5.1. アーキテクチャ・保守性 (NF-01)

* **レイヤー分離の踏襲**: 既存の TODO アプリ（`src/apps/todo/`）の設計パターンに準拠し、`src/apps/ai/` 配下に以下の責務分離を行う。
* **Router (`aiRouter.ts`)**: URLパスとHTTPメソッドの定義、コントローラーメソッドへのマッピングのみを担当。
* **Controller (`aiController.ts`)**: リクエストの受付、バリデーション実行、HTTPステータス・レスポンス整形、例外時の `next(err)` 呼び出しを担当。
* **Service (`aiService.ts`)**: `@google/genai` SDKの呼び出し、プロンプト構築、タイムアウト制御、外部API例外のラップを担当（Expressの `req` / `res` に依存させない）。


* **型安全性**: TypeScript の厳格な型チェックに準拠し、`any` 型の使用を禁止する。リクエストボディ・レスポンスDTOおよびカスタムエラーの型定義を明示する。

### 5.2. セキュリティ要件 (NF-02)

* **機密情報保護**:
* `AI_API_KEY` は `.env` ファイルおよび実行環境の環境変数でのみ管理し、ソースコードへのハードコーディングを禁止する。
* APIキーおよび内部エラーのスタックトレースをクライアント側（HTML、JS、APIレスポンス）およびエラーログへ一切露出させない。


* **XSS（クロスサイトスクリプティング）対策**:
* EJSテンプレート内での変数展開には必ずHTMLエスケープタグ（`<%= ... %>`）を使用し、非エスケープ出力（`<%- ... %>`）を使用しない。
* フロントエンド（`public/ai/ai.js`）でAIの回答やエラー文をDOMへ描画する際は `textContent` を使用し、未サニタイズの文字列に対する `innerHTML` の使用を禁止する。



### 5.3. 性能・可用性・操作性 (NF-03)

* **タイムアウト基準**: Gemini API へのリクエストタイムアウト時間は **30秒（30,000ms）** を基準とする。
* **二重送信防止**: 質問送信ボタンを押下してからAPIレスポンスを受信（またはエラー確定）するまでの間、送信ボタンおよび入力欄を非活性（`disabled`）状態にし、重複リクエストを防止する。
* **プロセス可用性**: 外部APIの通信障害や不正リクエストによって Node.js プロセスが未捕捉例外でクラッシュしないこと。

### 5.4. 既存機能への非干渉要件 (NF-04)

* 既存の TODO アプリケーション（`src/apps/todo/`）、データベース接続処理、共通ミドルウェアの動作を一切変更・破壊しないこと。
* `index.ts` に `app.use('/ai', aiRouter)` を追加する際は、既存の404ハンドリングミドルウェアおよびグローバルエラーハンドリングミドルウェアよりも**前**に定義し、既存のルーティング解決順序に影響を与えないこと。

## 7. 受け入れ基準（完了条件）

本機能の実装完了およびリリース判定には、以下のすべての条件を満たすことを必須とする。

1. **画面表示**: `GET /ai` にアクセスした際、AI質問画面が正常にレンダリングされ、既存画面との相互遷移リンクが機能すること。
2. **正常系応答**: 1文字以上 1,000文字以下の有効な質問を送信した際、ローディング表示を経て `gemini-3.5-flash-lite`（または `AI_MODEL` で指定したモデル）からの回答が画面内に適切に表示されること。
3. **入力バリデーション**: 空文字、スペースのみの入力、1,001文字以上の入力を行った際、適切なエラーメッセージが表示され、不要な外部API通信が発生しないこと。
4. **異常系耐性**: APIキー不正・未設定、タイムアウト、通信エラー発生時にもサーバープロセスが停止せず、画面上にユーザーフレンドリーなエラーメッセージが表示されること。
5. **セキュリティ**: ブラウザの開発者ツール（ネットワーク通信・ソース表示）上で `AI_API_KEY` が閲覧できないこと。また、HTMLタグを含む質問・回答でもスクリプト実行（XSS）が発生しないこと。
6. **既存機能回帰確認**: 既存の TODO 一覧表示・追加・更新・削除および存在しないURLへの404応答が、機能追加前と変わらず正常に動作すること。
