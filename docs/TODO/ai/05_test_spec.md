# AI質問機能 テスト仕様書 (`05_test_spec.md`)

## 1. 文書概要・テスト方針

### 1.1. 文書の位置づけ

本書は「AI質問機能 要件定義書 (`02_requirements.md`)」「設計書 (`03_design.md`)」「実装手順書 (`04_implementation.md`)」にもとづき、実装された AI質問機能（標準モデル: **`gemini-3.5-flash-lite`**）がすべての機能要件・非機能要件および受け入れ基準を満たしているかを検証するためのテスト仕様書である。

### 1.2. テスト目的と合格基準

* **機能網羅性**: 画面表示・非同期送信・文字数制御・回答描画・クリア機能・バリデーション・例外ハンドリングが設計通りに動作すること。
* **異常系耐性**: 不正入力・APIキー不備・タイムアウト・通信障害時にも Node.js プロセスがクラッシュせず、ユーザーへ適切なエラーメッセージが返却されること。
* **セキュリティ担保**: APIキーがクライアントやログへ漏洩せず、HTML/JavaScript インジェクション（XSS）が完全に防止されていること。
* **非干渉性**: 既存の TODO アプリケーションおよび 404 / グローバルエラーハンドリングにデグレードが発生していないこと。
* **合格基準**: 本仕様書の全テストケース（`TC-UI` / `TC-API` / `TC-VAL` / `TC-ERR` / `TC-SEC` / `TC-REG`）において、期待結果と実績が一致し、重大・中程度の不具合が 0 件であること。

### 4.3. 入力バリデーションテスト（異常系・境界値）

フロントエンドの事前検証をバイパスし、`curl` 等で `POST /ai/ask` に直接リクエストを送信してバックエンドの検証ロジックを確認する。

## 5. バックエンドAPI検証用 `curl` コマンド集

テスターがターミナルから `TC-API` および `TC-VAL` を迅速に検証するためのコマンド例（ポート `3000` の場合）。

```bash
# 1. 正常系 (TC-API-01)
curl -i -X POST http://localhost:3000/ai/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"ExpressとTypeScriptの利点を簡潔に教えてください"}'

# 2. 異常系: 空文字 (TC-VAL-03 -> 400 Bad Request)
curl -i -X POST http://localhost:3000/ai/ask \
  -H "Content-Type: application/json" \
  -d '{"question":""}'

# 3. 異常系: スペース・改行のみ (TC-VAL-04 -> 400 Bad Request)
curl -i -X POST http://localhost:3000/ai/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"    \n  "}'

# 4. 異常系: 型不正 (TC-VAL-02 -> 400 Bad Request)
curl -i -X POST http://localhost:3000/ai/ask \
  -H "Content-Type: application/json" \
  -d '{"question":12345}'

# 5. 異常系: 1,001文字超過 (TC-VAL-05 -> 400 Bad Request)
node -e 'console.log(JSON.stringify({ question: "あ".repeat(1001) }))' | \
  curl -i -X POST http://localhost:3000/ai/ask \
  -H "Content-Type: application/json" \
  --data-binary @-

```
